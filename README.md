# 高分子材料图鉴

中文材料知识库，包含130条材料记录、分类搜索、收藏、材料对比与基础术语。

## 静态部署

发布目录：`dist`。图鉴本身（`index.html` + `app.js`）无构建步骤；`dist/` 里的派生产物（新闻归档、材料页、可下载 Excel、`robots.txt` / `sitemap.xml`）由 `npm run build` 一次性重建，生成结果随仓库提交。

```bash
npm run build    # 依序：新闻归档 → 材料页预渲染 → 可下载 Excel → sitemap
npm run serve    # 本地预览 http://localhost:8080
```

资料核验范围见每条记录；研究构思不等同于已验证实验结果。收藏保存在访问者当前浏览器。

## 材料的独立页面（预渲染）

每条材料都有一份真实存在的静态页：`dist/m/<id>/index.html`，线上地址形如 `/m/m-0-0/`；每个材料分类另有一份分类页：`dist/c/<slug>/index.html`，线上地址形如 `/c/elastomers/`。

为什么要单独做这一层：图鉴是纯前端渲染的，材料正文只存在于 `data.json` 里，搜索引擎只看得到一个根地址。预渲染之后，每条材料有自己的地址、标题、描述、canonical 和分享卡片，被 `sitemap.xml` 收录，并通过「关联材料」与「同分类的其他材料」互相链接，成为一张可爬取的图。页面不加载 `app.js`——它的定位是内容页，读取快、关掉 JS 也读得完；搜索、对比、收藏留在图鉴里，页面上给了回链（`/#materials/<id>`，图鉴会自动展开那条材料）。

这里的「关联材料」直接调用图鉴那份 `dist/learning.js` 的 `relatedMaterials()`，理由（正文提到／Tg 差 8 ℃／同分类）一字不差地搬过来，说明句也共用 `RELATED_NOTE` 常量。**同一份推荐不在两处各算一次**——否则从搜索引擎落到独立页的读者，和图鉴里的读者会看到两条不同的推荐顺序。互链已经这么处理过一次（`linkifyMaterials` 在 `app.js` 与 `prerender.mjs` 各有一份，规则必须一致），关联材料这次改成共用同一份实现，不再复制逻辑。列表里已关联过的材料从下面的「同分类的其他材料」中剔除，免得同一页出现两个指向同一处的链接。

分类页补的是这张链接图里缺的一层枢纽：材料页只会横向连到同类的十几条，9 个分类页各自列出本类全部材料并互链到其他分类，既让「橡胶弹性体这一类」能被单独分享，也给爬虫一条从首页直达任意材料的中间路。分类的地址片段登记在 `scripts/site.mjs` 的 `CATEGORY_SLUGS`——data.json 里出现没登记的新分类时，构建会直接失败并提示补上，而不是生成一串百分号编码的地址。

- 生成器：`scripts/prerender.mjs`（字段分组与 `app.js` 的 `detailGroups` 对齐，脚本会检查 data.json 的每个字段都被收录，漏了直接报错）
- 版式：`dist/material.css`，只补这一页独有的骨架，颜色与组件复用 `style.css` / `layout.css`
- 站点地址可用环境变量 `SITE_ORIGIN` 覆盖（绑定自定义域名后不用改代码）
- `wrangler.jsonc` 里显式声明了 `html_handling: auto-trailing-slash`，`/m/<id>/` 与 `/c/<slug>/` 由这个策略解析到各自的 `index.html`

## 可下载的 Excel

首页「下载完整 Excel」指向 `dist/materials.xlsx`：九个材料分类各一张表，另有术语表。

它由 `scripts/build-xlsx.py` 从 `data.json` / `terms.json` 生成。此前它是一份手工维护的第二份副本，不受任何检查约束——改了 JSON 忘了改表，读者下载到的就是过期内容，而且没人会发现。改成派生文件之后，它与站点展示的内容同源同批次。

术语取 `terms.json` 的 68 条正式词条，而不是 `data.json` 内嵌的那一份：后者只是 `terms.json` 加载失败时的回退数据，条数少且会过时。

生成与校验依赖 `openpyxl`，与分享卡片用到的 Pillow 一并列在 `scripts/requirements.txt`：

```bash
pip install -r scripts/requirements.txt
```

## 材料数值

每条材料可选填 `Tg` / `Tm` / `HDT` / `密度` / `加工温度` 五个数值，用于「耐温 > 150 ℃ 且密度 < 1.1」这类筛选。数据在 `data.json` 的 `materials[].props`，字段定义是同文件的 `propsSpec`（唯一来源）。

同一份数值出现在五处：材料详情的数值块、列表的数值筛选器、按数值排序时卡片上的读数、对比表的数值表、可下载的 Excel。**新增一处展示要同步这五处**，否则会出现「网页上有、下载的表里没有」这类衔接缺口。

按数值排序时，每张卡片会多一行「密度 0.86 g/cm³」这样的读数，没填的显示「—」。不加这行的话，按密度排完却看不出密度，读者只能选择相信排对了——而排序恰恰是最该被检验的操作。默认顺序与按名称排不显示。

填表流程：`python scripts/build-props-sheet.py` 生成 `props-待填.xlsx` → 填好 → `python scripts/apply-props.py <表>` → `npm run build`。表格里留空表示「不改动」，已填的值不会因为这次留空被清掉——正因为如此，**要删掉一个已经填过的值，得直接改 `data.json`（或写新值覆盖），在表里把它清空是删不掉的**。

口径三条，看数之前先看这里：

1. **值为典型值**，取未改性、通用牌号，不是某个厂商某个牌号的数据。牌号差异大的材料（LCP、PPA、改性 PP）备注里会写明。
2. **HDT 统一按 0.45 MPa**。同样的材料 1.8 MPa 下要低 30–50 ℃，两个条件混着比会得出错误结论。
3. **没有物理意义的格子留空**，不是填 0：热固性树脂没有 Tm、纤维没有 HDT、橡胶的「加工温度」不是熔融窗口。筛选器的语义是「填了条件＝要求该材料必须有这个数」，所以没填的材料不会出现在筛选结果里——这是刻意的，不把「没数据」伪装成「不符合」。

覆盖情况随数据增长，`npm run check` 里的 `audit` 会报当前条数。

有 8 条材料完全没有数值，不是漏填：透明质酸、聚噻吩、光刻胶、高分子表面活性剂、药物载体、形状记忆、自修复、热电高分子——它们的数值随配方或使用条件变（形状记忆的转变温度本身就是设计参数），给一个「典型值」反而会误导选型。这些材料在 `materials[].propsNote` 里写明了原因，详情页与材料独立页都从这一个字段读，不各写一份。新增同类材料时照着写一句，否则读者会以为资料没整理完。

对比选择（「加入对比」勾的材料）存在本机 `localStorage` 的 `polymer-atlas-compare`，刷新和下次打开都还在。恢复时会剔掉已经不存在的 id、去重、并按 3 条上限截断，收拾干净后写回。

对比结果可以带走，三个按钮都在对比表右上角：

- **复制表格**：TSV 格式，直接粘进 Excel / 腾讯文档就是一张表；表头是「缩写（全名）」，没填的数值写「—」不用 0 冒充。勾了「只看差异」就只带屏幕上剩下的行。
- **打印 / 存为 PDF**：只印对比表本身（底下的材料详情不会跟着印），纸上有页眉（标题、材料缩写、日期、站点地址）、每页重复表头、行不跨页断开。
- **复制分享链接**：形如 `/?compare=<id>,<id>#materials`。打开自动摆好这张对比表，参数用一次就从地址里抹掉（否则改完勾选再刷新会被旧参数拉回去）；链接指向 canonical 公开地址——EdgeOne 镜像要令牌才能进，发当前地址给同事对方会吃 401。

## 筛选与排序的状态放在地址里

列表的筛选条件写在查询串上，刷新不丢、可以直接把地址发给别人：

```
/?q=PET&c=工程塑料&sort=密度&dir=desc&密度-max=0.95#materials
```

（查询串在 `#` 前面——哈希是浏览器自己消费的，参数塞进哈希里 `URLSearchParams` 就读不到了。中文会按百分号编码，地址看起来长一点，换来的是人也能读懂。）

| 参数                        | 含义                                                      |
| --------------------------- | --------------------------------------------------------- |
| `q`                         | 搜索词                                                    |
| `c`                         | 分类（省略＝全部材料）                                    |
| `f=1`                       | 只看收藏                                                  |
| `sort` / `dir`              | 排序字段与方向（`default` 时省略）                        |
| `<字段>-min` / `<字段>-max` | 数值条件，字段名取自 `propsSpec`，如 `Tg-min`、`密度-max` |

三条规矩，改这块之前先看：

- **只 `replaceState`，不 `pushState`**。搜索框每敲一个字都算一条历史记录的话，返回键要一个字一个字往回退。
- **只增删自己认识的参数**。EdgeOne 预览链接把 `eo_token` / `eo_time` 挂在查询串上，整串重写会把它们抹掉，链接当场失效。
- **哈希仍然只管「打开的是哪一条」**（`#materials/<id>`），查询串只管「看的是哪一批」。两者各管一段，不要互相覆盖。

排序里「没填数值」的记录一律沉底，升序降序都不翻面——翻过来会让「没测过」排在最前面，比排最后更像结论。

有条件时结果标题行右侧会出现「清除筛选」，一次清掉搜索、分类、只看收藏、数值条件与排序（术语页则是搜索与主题）。它只在**确实有条件**时出现：一个点不动的按钮摆在那里，只会让人以为它坏了。`hasFilters()` 不把「我的收藏」算作条件——那是换了看的范围，不是把范围收窄，清掉它只会让人以为东西丢了；它也按视图分开判断，免得在术语页选过主题后切回来，材料页莫名多出一颗按钮。

结果为空时会说清是哪一层把它清空的。数值筛选的语义是「填了条件＝要求该材料必须有这个数」，所以一条都没有**不一定是搜错了**——很可能是这些材料的数值还没整理。这时文案会报出「N 条没有填这项数值，M 条填了但不在区间内」，而不是笼统地让人去改关键词。

详情里的「关联材料」按三类理由排序，每条都把理由写在卡片上：正文提到对方全名的排最前，其次是同分类里数值最接近的（写出差多少，加工温度按区间重叠与否分三种说法），最后才是「同分类」兜底。三组写死的家族关系（聚酯、聚酰胺/嵌段弹性体、聚苯醚合金）仍然优先。**理由必须能从数据反算**：`related-e2e.mjs` 会把每条标签拿回 `data.json` 核对一遍，改坏了对不上就掉。没有数值也没有互相提及的材料，标签如实写「同分类」，不编一个数值出来。

反向也有入口：术语详情与正文高亮弹出的速读卡里，会列出「正文提到这一概念的材料」，按提及次数排、最多 6 条，点进去直接换到那份资料。匹配用的是正文高亮同一份 `termAliases`，所以不会出现「正文里高亮着、这里却说没有材料提到」的矛盾；别名表里没有的术语（68 条里大部分是复合概念名）就不显示这一块，不拿关键词硬凑。

## 本地校验

```bash
npm run check    # 提交前跑一次，四步全过才算干净
```

- `npm run check:derived` —— 两步。先看新闻归档：用 `news.json` 重建索引与月度文件，与仓库现有内容不一致即失败，专治「只改了 `news.json`，忘了同步派生文件」。再看可下载的 Excel：`dist/materials.xlsx` 由 `scripts/build-xlsx.py` 从 JSON 生成，`check-xlsx.py` 读回来逐格比对，专治「改了数据忘了重新生成，读者下载到过期内容」。
- `npm run check:prerender` —— 逐字节比对 130 份材料页与 9 个分类页跟 `data.json` 当前内容。专治「改了数据，忘了重跑预渲染」——漏一页就是 sitemap 少收录一条内容，而且不会有任何报错。
- `npm run check:seo` —— 校验首页与 `news.html` 的分享卡片信息，并要求每个分类、每条材料都有预渲染页，然后与 `robots.txt` / `sitemap.xml` 对账。
- `npm run audit` —— 校验 id / url 去重、必填字段、日期合法性、月度分档并集、索引覆盖等。数据错误时命令返回非 0；工程习惯类问题只告警，不拦截提交。

另有 `npm run check:links` 单独查链接：dist 下全部 HTML（含材料页）的站内引用必须存在，数据文件里的外链逐一探测可达性。401/403/429 这类「站点在但拒绝脚本」不计为失效，连不上默认只告警。

`.github/workflows/audit.yml` 会在 `dist/**` 或脚本变更时自动执行上述检查，并每天定时跑一次链接检查，结果写入 job summary。

## 材料动态

`dist/news.html` 提供短摘要、原始来源、材料/类型/月度筛选和分页历史归档。新闻存档为 `dist/news.json`，更新流程见 `NEWS_UPDATE.md`。

## 部署

Cloudflare Workers，配置在根目录 `wrangler.jsonc`，发布目录 `dist`。

push 到 `main` 会自动部署：仓库已接入 Cloudflare Workers Builds（Workers & Pages → 该 Worker → 设置 → 构建 → Git 集成），Cloudflare 自己监视 `main`、拉取仓库并上传 `dist`，GitHub 侧不需要配任何 secret，每次推送会在 PR/commit 上出现一条「Workers Builds」检查。

CI 里因此**没有**部署工作流——两套部署机制同时开，一次推送会传两遍、还会在版本历史里互相顶替；GitHub Actions 也不能在 job 级 `if` 里引用 `secrets`，硬写只会让每次推送都挂一个红叉。手动部署仍可用：

```bash
npx wrangler deploy    # 首次需要先 wrangler login
```

GitHub 仓库私有不代表已部署的网站私有。
